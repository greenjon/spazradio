reviewed. The per-lane detail, with Where, Evidence and Fix for each finding, is in `audit-2026-11-26/<lanes>.md`.

- `testDebugUnitTest assembleRelease lintDebug` passes. 51 unit tests ran and none failed.

## A. Bugs

Playback and service:
- A1-1: unplugging headphones does not pause playback (no `setHandleAudioBecomingNoisy`).
- A1-2: reopening the app replaces an archive that is playing in the background with the live stream.
- A1-3: "Reconnecting…" is shown, but nothing retries after an error or end of stream.
- A1-4: the notification and lock-screen title stay blank until the song changes.
- A1-5 (uncertain): there is no wake mode for streaming, and the declared `WAKE_LOCK` is unused.
- A5-1: the built-in EQ keeps the old sample rate's filters after a format change. `onFlush` should reset
  `applied`.

Archive and downloads:
- A3-1: downloads fail silently on Android 7-9, because `WRITE_EXTERNAL_STORAGE` is missing.
- A3-2: one malformed feed item cuts the archive list short.
- A3-3 (uncertain): after a reinstall, downloaded shows can look not-downloaded and get downloaded twice.
- A3-4: the downloading set uses a non-atomic read-modify-write from two threads.

Schedule and UI:
- A2-2: one schedule row with a null `name` blanks the whole schedule.
- A7-3: AUTO theme under system dark draws the wrong system-bar icons.
- A7-4: in Neon, the "Reset Chat Username" button text is about 1.7:1 contrast.

Chat (the broker is open):
- A4-1: messages are rendered as HTML, with auto-linking.
- A4-2: `onCleared` never disconnects, because it launches on a cancelled scope.
- A4-3 (uncertain): a disconnect while the link is down leaves the old client auto-reconnecting.
- A4-4: the presence clear races the disconnect.
- A4-5: a reconnect in the background marks the user online again.
- A4-6: the presence roster is unbounded.

Network and security:
- A8-1: two HTTP clients trust every certificate and hostname: `SpazNetwork` (chat history) and the dead
  `MetadataViewModel`.
- A8-3: shared logs include the chat nickname, and the dump runs on the main thread.
- A8-9: `NetworkMonitor` reports offline when one of several networks drops.

Visuals:
- A6-3 (uncertain): the oscilloscope fallback can crash on a zero size, and its 30 fps loop never stops.

Upstream (liquid-lsd `android/lsd-visuals`, fix there and resync):
- A8-4: "Check now" and the daily content job share one staging folder.
- A8-5: activating new content deletes the folder a running picture still reads from.

## B. Docs and policy say something false

- A2-5: the schedule error state shows "Connecting…".
- A4-7: a failed send throws away the draft.
- A4-8: the nickname and outgoing text are neither trimmed nor capped (the web TV caps them).
- A7-1: there is hard-coded English in composables, although translated strings exist.
- A8-2: `PRIVACY.md` omits the background content check, the live relay, the public nickname and chat log, what
  logs contain, and why each permission is needed.
- A8-7: the backup rules are untouched templates, so downloaded content (up to 20 MB) is backed up.
- A9-5: a release build with no signing secrets silently gets the debug key.
- A9-6: the workflows never run tests. Nightly publishes a public pre-release with a wrong version on every push.
- A10-5: the in-app privacy link goes to the repo root, and its text claims more than the policy does.
