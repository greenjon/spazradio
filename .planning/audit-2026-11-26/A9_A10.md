### A9-5 [wrong] A release build with no signing secrets silently gets the debug key; the tag workflow relies on it
- Where: `app/build.gradle.kts:50-55`; `.github/workflows/release.yml:46-60, 62-71`
- Evidence: if `KEYSTORE_PATH`, password or alias is missing, `initWith(getByName("debug"))` is used with no warning, so `./gradlew assembleRelease` on any machine without `key.properties` produces a debug-signed `app-release.apk`. `release.yml` deliberately generates a debug keystore when `RELEASE_KEYSTORE_BASE64` is unset (it is not set; the comment on lines 11-12 says CI has no signing key). Secret handling itself is fine: the keystore is written to `app/release.jks` (gitignored) and passwords go through `env:` on the build step only, never echoed. Note `KEYSTORE_PATH` is exported even when no secret exists, pointing at a file that does not exist; the `File(storePath).exists()` check at line 50 protects that.
- Impact: a local `assembleRelease` on a fresh checkout, or someone running `fastlane build_standalone_apk` without key.properties, ships a debug-signed APK that cannot update a Play or master-key install. Beta tag APKs are intentionally debug-signed (documented in 2.0.0 notes only as "different signing key").
- Fix: when `-PuseMasterKey` or a `release` task is requested and the key is missing, fail the build (`throw GradleException`) unless an explicit `-PallowDebugSigning` is given; have `release.yml` pass that flag.
